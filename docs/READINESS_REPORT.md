# 장기 백업·복구 준비 검증 결과

작성일: 2026-10-21. 현재 소스는 미커밋 상태이며 GitHub에 push하지 않았다.

## 준비한 항목

- 활성 전체 소스·테스트·기존 대안 소스를 보존했다.
- 실제 NAS 구성 조사와 한글 설치·업데이트·백업·복원·버전 관리 문서를 추가했다.
- 루트 Stack/Compose를 현재 운영 서비스·마운트·환경에 맞췄다.
- 기존 이미지에서 Python 의존성 31개와 Chromaprint/FFmpeg 라이선스를 수집했다.
- 빌드 의존성 제약, 최소 Docker context, 배포 허용 목록, CI 검증을 연결했다.
- .gitignore는 실제 키·설정·음악·data·백업·Git bundle을 제외한다.

## 보안 및 별도 보관 항목

현재 주소·계정·실제 경로는 이번 사용자 지시에 따라 CURRENT_NAS.md와 YAML에 포함한다.
이는 의도한 비공개 운영 메타데이터다. 비밀번호·개인키 내용·실제 API 키는 기록하지 않는다.
deploy-nas.local.json은 기존 실제 값을 유지하면서 Git에서 제외한다.
음악·data·키·이미지 archive의 별도 백업이 없으면 완전한 사용자 환경 복구는 불가능하다.
기존 Git 기록은 보존했으며 첫 커밋의 과거 경로·도메인도 그대로 남는다.

## 검증 상태

- 필수 복구 파일·배포 허용 목록·직접 의존성/잠금 일치·문서 링크 검사 통과.
- 기존 UI 핸들러 2종, Git 제외 규칙, PowerShell 배포/설정 거부 테스트 통과.
- 잠금 버전으로 별도 이미지 `music-tag-filler-validation:recovery-20261021` 빌드 성공.
  이미지 ID: `sha256:a11ae11960579ece9f120f6261ed154496f939701311dfd248f89a20cdc3a82a`.
- 위 새 이미지에서 운영 볼륨 없이 생성 음원 **55개 통과, 실패·스킵 0**.
- 저장소의 현재 Stack YAML과 새 이미지 기본값을 실제 운영 설정과 대조하여 일치 확인.
- 기존 자동 배포의 로컬/읽기 전용 preflight 통과. 실제 파일 전송·운영 빌드·재생성은 하지 않음.
- 비밀값/원본 데이터 검사에서 실제 키·음악·상태 파일 미발견. 운영 메타데이터는 사용자 승인으로 포함.
- 의존성 31개 OSV 검사에서 **4개 패키지에 보안 공지 79개 레코드** 일치.
  중복 별칭을 포함하며 독립 CVE 개수가 아니다. [보안 보고서](SECURITY_AUDIT_KO.md) 참고.

실제 NAS 신규 설치/운영 중지/data 백업/archive 복구/운영 재배포와 GitHub Actions
실행은 하지 않았다. GitHub 인증과 비공개 상태, ARM 이전, 이미지 OS 패키지 CVE,
전체 프로젝트 최상위 라이선스 지정은 미완료다. 운영 컨테이너와 음악은 그대로 유지했다.
별도 검증 폴더/이미지는 재현용으로 남겼다.

기존 HEAD `540725e7904ece20ec3b4d4757ed8da580585e81`와 커밋 1개는 유지하며
stage·commit·push·태그·원격 등록을 하지 않는다.

## 사용 한도 중단 후 최종 확인

- 기존 수정 파일과 위 검증 기록을 먼저 확인했다. 완료한 이미지 빌드·55개 회귀·OSV 조회는 반복하지 않았다.
- Git에서 제외되는 `scratch/yaml-validator/`에 테스트 전용 YAML 파서를 설치하고,
  CI·Stack·Compose를 엄격한 YAML 1.2 문법으로 파싱했다. 오류 없음,
  CI 읽기 전용 권한·검증 작업 2개·두 YAML 일치·음악 읽기 전용 조건을 확인했다.
  파서는 앱/Docker 의존성에 추가하지 않았고 Git 업로드 대상에도 포함되지 않는다.
- 백업 명령 예시의 정상 종료 경로에 명시적인 v6 재시작을 추가했다.
  셸 종료를 기다려야 재시작하던 문서상 문제를 수정한 것으로, 실제 중지/시작은 하지 않았다.
- NAS 최종 상태 확인을 재시도했지만 SSH 22번 포트에서 `Connection refused`가 발생했다.
  따라서 이번 재개 시점의 운영 이미지·가동 상태·마운트는 재확인하지 못했다.
  앞서 성공한 조사/preflight 결과는 당시 기록이며 최신 상태 확인을 대신하지 않는다.
  SSH·방화벽·Docker·권한·데이터를 변경하거나 연결 문제를 우회하지 않았다.
- 원격 GitHub Actions 실행·실제 신규 설치·백업/archive 복원 훈련은 여전히 미실행이다.
